## О проекте

Решение тестового задания на стажировку Авито: сервис бронирования переговорок.

## Что реализовано

Обязательная часть:
- роли `admin` и `user` с JWT авторизацией
- управление переговорками (`rooms`) и расписаниями (`schedules`)
- просмотр доступных слотов по комнате и дате
- создание и отмена брони
- список всех броней для admin с пагинацией
- список будущих броней текущего пользователя
- `GET /_info` (возвращает `200`)

Дополнительная часть:
- регистрация и авторизация пользователей (`/register`, `/login`)
- `createConferenceLink` при создании брони
- Makefile
- unit и e2e тесты
- нагрузочное тестирование
- конфигурация линтера

Генерация слотов:
- слоты создаются лениво при запросе `GET /rooms/:roomId/slots/list?date=YYYY-MM-DD`
- шаг слота фиксирован: 30 минут

В условии было сказано возвращать для `/bookings/my` только брони на будущие слоты, но не сказано про статус брони, поэтому в моей реализации выводятся как активные, так и отмененные брони

## Запуск

```bash
make up
```

Примечание: `Makefile` использует `include .env`, поэтому для `make` нужен файл `.env` в корне.

Сервис поднимается на `http://localhost:8080`.

Полезные URL:
- Swagger UI: `http://localhost:8080/swagger/index.html`
- Healthz: `http://localhost:8080/_info`

## Тесты

```bash
make tests
```

Покрыты сценарии:
- создание комнаты -> расписания -> брони
- отмена брони

## Seed данных

```bash
make seed
```

`db/seed.sql` загружает датасет для нагрузочного профиля:
- до 50 комнат
- до 10 000 пользователей
- до 100 000 слотов
- до 100 000 броней

## Нагрузочное тестирование
